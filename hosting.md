# Deployment & Hosting Guide — ForMe Store

This document explains the **complete end-to-end deployment process** used to host **ForMe Store** (`frontend/` React + Vite SPA, `backend/` Node.js/Express API, and MongoDB Atlas) on **AWS EC2** using **CloudFormation**, **AWS SSM Parameter Store**, **Nginx**, **PM2**, and **GitHub Actions**.

## 1. Architecture & How Everything Connects

Your deployment uses a **single-server reverse-proxy architecture** on AWS EC2 paired with an external managed database (MongoDB Atlas):

```
                            [ USER / BROWSER ]
                                    │
                                    │ HTTP (Port 80)
                                    ▼
                  ┌───────────────────────────────────┐
                  │          AWS EC2 INSTANCE         │
                  │     Ubuntu 24.04 LTS (t2.micro)   │
                  │                                   │
                  │   ┌───────────────────────────┐   │
                  │   │    NGINX (Port 80)        │   │
                  │   │    Reverse Proxy &        │   │
                  │   │    Static Web Server      │   │
                  │   └─────────────┬─────────────┘   │
                  │                 │                 │
                  │    ┌────────────┴───────────┐     │
                  │    │                        │     │
                  │    ▼                        ▼     │
                  │  Frontend Build        Backend API│
                  │  /var/www/app/         (PM2 fork) │
                  │  frontend/dist         127.0.0.1: │
                  │                        5000       │
                  └─────────────────────────────┬─────┘
                                                │
                                                │ Mongoose (TLS)
                                                ▼
                                    [ MONGODB ATLAS ]
                                    M0 Cloud Database
```

### Why Each Tool Is in This Stack

| Tool | Role in Your Deployment |
|---|---|
| **AWS CloudFormation** (`infra/ec2-instance.yaml`) | Creates and tracks your EC2 instance, Security Group, and SSH key automatically as code—no manual AWS Console clicking needed. |
| **AWS SSM Parameter Store** | Automatically stores the private SSH key generated by CloudFormation so GitHub Actions can fetch it securely during deployment. |
| **GitHub Actions** (`.github/workflows/deploy.yml`) | Runs automatically on every push to `main`: verifies the frontend build, provisions/checks EC2, SSHes in, pulls code, builds assets, writes `.env`, and restarts services. |
| **Nginx** (`infra/nginx.conf`) | Listens publicly on port `80`, serves the compiled React app (`frontend/dist`), and forwards `/api/*` and `/uploads/*` requests to Express on port `5000`. |
| **PM2** (`backend/ecosystem.config.cjs`) | Runs the Node.js backend (`backend/src/server.js`) continuously in the background, restarts it on crashes, and restores it if the server reboots. |
| **MongoDB Atlas** | Hosts your database outside EC2 so product, user, cart, and order data persist even if the EC2 instance stops or is recreated. |

## 2. How Live Requests Flow (Runtime Walkthrough)

Because Nginx serves both the React frontend and proxies API calls on the same EC2 IP (`http://<EC2_IP>`), the browser always talks to a **single origin** on port `80`:

1. **Opening any page (`/`, `/shop`, `/products/:id`, `/admin`):**
   - Browser sends `GET http://<EC2_IP>/shop` to Nginx on port `80`.
   - Nginx checks `/var/www/app/frontend/dist`. Since `/shop` is a React Router route (not a physical folder), `try_files $uri $uri/ /index.html;` returns `index.html`, and React Router renders the Shop page.
2. **Calling the API (`/api/products`, `/api/auth/login`, `/api/orders`, etc.):**
   - Frontend Axios client sends requests to `/api/...` (same host and port `80`).
   - Nginx matches `location /api/` and proxies the request internally to `http://127.0.0.1:5000/api/...`.
   - Express processes the request, queries MongoDB Atlas, and sends JSON back through Nginx to the browser.
3. **Loading uploaded product/category images (`/uploads/products/...`, `/uploads/categorys/...`):**
   - `ProductImage.jsx` builds image URLs against the current origin (`http://<EC2_IP>/uploads/...`).
   - Nginx matches `location ^~ /uploads/` and forwards the request to Express (`http://127.0.0.1:5000/uploads/...`), which serves files from `backend/uploads/` via `express.static`.

## 3. How the Automated Deployment Pipeline Works (`git push` to Live)

Every time you push to `main` (or click **Run workflow** in GitHub Actions), `.github/workflows/deploy.yml` executes two sequential jobs:

### Job 1: `build` (Sanity Check in GitHub)
1. Checks out your repository.
2. Sets up Node.js 22 with npm caching keyed on `frontend/package-lock.json`.
3. Runs `npm ci` and `npm run build` inside `frontend/` with `VITE_API_URL=/api`.
4. If the frontend fails to compile, the workflow stops immediately before touching AWS.

### Job 2: `deploy` (Infrastructure + Server Deployment)
Runs only after `build` succeeds:
1. **Authenticate to AWS:** Loads `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, and `AWS_SESSION_TOKEN` from GitHub Secrets in `us-east-1`.
2. **Deploy CloudFormation Stack (`forme-store-stack`):**
   - Runs `aws cloudformation deploy --template-file infra/ec2-instance.yaml --no-fail-on-empty-changeset`.
   - **First run:** CloudFormation creates the SSH KeyPair, Security Group, and EC2 `t2.micro` instance, then runs the `UserData` bootstrap script to install Node.js 22, Nginx, Git, and PM2 and clone the repo into `/var/www/app`.
   - **Subsequent runs:** CloudFormation sees the stack already exists and leaves the running EC2 instance intact.
3. **Read Stack Outputs:**
   - Queries CloudFormation for `PublicIP` (the EC2 instance's current IPv4 address) and `SSMKeyPath` (`/ec2/keypair/<KeyPairId>`).
4. **Retrieve SSH Key from SSM:**
   - Calls `aws ssm get-parameter --name "$SSM_PATH" --with-decryption` to write the private key temporarily to `/tmp/server-key.pem` with `chmod 600`.
5. **Wait for SSH (Port 22):**
   - Polls `nc -zw5 "$IP" 22` up to 36 times (every 10 seconds, max 6 minutes) until the EC2 instance is ready to accept SSH connections.
6. **Deploy on EC2 via SSH (`appleboy/ssh-action`):**
   - **`[1/6]` Wait for `cloud-init`:** `sudo cloud-init status --wait || true` ensures first-boot `UserData` installation (Node.js, Nginx, PM2, initial `git clone`) has finished before running commands.
   - **`[2/6]` Update Code:** `cd /var/www/app && git fetch origin main && git reset --hard origin/main` syncs the server cleanly to the latest commit (while keeping untracked files like `backend/uploads/` and `backend/.env`).
   - **`[3/6]` Install Backend Dependencies:** `cd /var/www/app/backend && npm ci --omit=dev` installs production-only Node dependencies.
   - **`[4/6]` Generate `backend/.env`:** Writes `PORT=5000`, `NODE_ENV=production`, `CLIENT_URL=http://$EC2_IP`, `MONGODB_URI`, `JWT_SECRET`, `JWT_EXPIRES_IN=1d`, and `DELIVERY_FEE_NPR=150` from GitHub Secrets and the live EC2 IP.
   - **`[5/6]` Build Frontend on EC2:** `cd /var/www/app/frontend && npm ci && VITE_API_URL=/api npm run build` compiles the latest React bundle into `/var/www/app/frontend/dist`.
   - **`[6/6]` Reload Services:** Stops old PM2 processes, starts `backend/ecosystem.config.cjs` with `--update-env`, saves the PM2 process list (`pm2 save`), copies `infra/nginx.conf` to `/etc/nginx/sites-available/app`, verifies syntax (`sudo nginx -t`), and reloads Nginx.
7. **Print URL & Clean Up:**
   - Prints `Live URL: http://<EC2_IP>` in the workflow logs.
   - Deletes `/tmp/server-key.pem` (`if: always()`) so no key remains on the GitHub runner.

## 4. Detailed Explanation of Every Configuration File

### A. `infra/ec2-instance.yaml` (CloudFormation Infrastructure)
- **Parameters:**
  - `InstanceType`: Defaults to `t2.micro` (AWS free-tier / Learner Lab eligible).
  - `UbuntuAMI`: Defaults to `ami-0e86e20dae9224db8` (Ubuntu 24.04 LTS in `us-east-1`).
  - `SSHLocation`: Defaults to `0.0.0.0/0` because GitHub Actions runners use dynamic IP addresses.
- **Resources:**
  - `ServerKeyPair`: Creates `${AWS::StackName}-key` and automatically registers the private key in SSM Parameter Store.
  - `ServerSecurityGroup`: Opens TCP port `80` (HTTP web traffic) and TCP port `22` (SSH for GitHub Actions).
  - `ServerInstance`: Launches EC2 with `UserData` that installs Node.js 22, Nginx, Git, PM2, clones `https://github.com/aakritipokharel/forme_store.git` to `/var/www/app`, links `infra/nginx.conf`, sets `ubuntu` ownership on `/var/www/app`, and configures `pm2 startup systemd` for automatic reboot recovery.
  - *Important:* Because `git clone` uses HTTPS without a token, the GitHub repository must be **public**.

### B. `infra/nginx.conf` (Web Server & Reverse Proxy)
- `listen 80;` / `server_name _;`: Accepts HTTP requests on any IP or hostname.
- `client_max_body_size 15M;`: Allows request bodies up to 15 MB (covering the 5 MB image upload limit in `backend/src/middleware/imageUpload.js`).
- `root /var/www/app/frontend/dist;`: Serves Vite's compiled frontend output.
- `location / { try_files $uri $uri/ /index.html; }`: Enables client-side routing across all storefront pages and `/admin/*` routes.
- `location /api/`: Proxies API calls to `http://127.0.0.1:5000/api/` and forwards `Host`, `X-Real-IP`, `X-Forwarded-For`, and `X-Forwarded-Proto` headers.
- `location ^~ /uploads/`: Proxies uploaded images to `http://127.0.0.1:5000/uploads/`. The `^~` modifier stops Nginx from matching the `.jpg`/`.png`/`.webp` static regex block below it (without `^~`, Nginx would look in `frontend/dist/uploads/...` and return `404`).
- `location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg|woff|woff2)$`: Adds 30-day browser cache headers for compiled static frontend assets.

### C. `backend/ecosystem.config.cjs` (PM2 Configuration)
- `name: 'forme-backend'`
- `script: 'src/server.js'` and `cwd: '/var/www/app/backend'`: Runs the Express entry point from the backend folder so relative paths and `dotenv` resolve properly.
- `exec_mode: 'fork'` and `instances: 1`: Essential on a single-vCPU `t2.micro` instance; PM2 `cluster` mode can cause `SIGINT` crash loops on low-memory single-core VMs.
- `max_memory_restart: '300M'`: Prevents memory leaks from exhausting the `t2.micro` instance's 1 GB RAM.

## 5. Application Code Configuration for Production

A few settings in the app code itself work together with Nginx and `.env` in production:

- **API Base URL (`frontend/src/services/api.js`):**
  ```javascript
  baseURL:
    import.meta.env.VITE_API_URL ||
    (import.meta.env.PROD ? '/api' : 'http://localhost:5000/api'),
  ```
  In local development (`npm run dev`), it uses `http://localhost:5000/api`. In production builds (`npm run build`), it uses `/api` so requests go to the live EC2 origin and through Nginx rather than the user's own `localhost`.
- **Uploaded Image URLs (`frontend/src/components/ProductImage.jsx`):**
  Uses the same `import.meta.env.PROD ? '/api' : 'http://localhost:5000/api'` fallback to derive `apiOrigin` (`http://<EC2_IP>` in production), turning database paths like `/uploads/products/xyz.jpg` into valid live URLs.
- **CORS (`backend/src/app.js`):**
  Uses `origin: process.env.CLIENT_URL || 'http://localhost:5173'`. Because `deploy.yml` writes `CLIENT_URL=http://$EC2_IP` into `backend/.env`, CORS matches the live server IP automatically.
- **Health Endpoint (`backend/src/app.js`):**
  `GET /api/health` returns `{ success: true, message: "Clothing store API is running", data: { status: "ok" } }` for quick verification.

## 6. Step-by-Step Setup From Scratch

### Step 1: Set Up MongoDB Atlas
1. Create a free account at [MongoDB Atlas](https://cloud.mongodb.com/) and provision an **M0 Free Cluster**.
2. In **Database Access**, create a database user with read/write permissions.
3. In **Network Access**, add `0.0.0.0/0` (**Allow Access from Anywhere**). This is required because EC2 public IPs change when an AWS Learner Lab instance stops and restarts.
4. In **Database → Connect → Drivers**, copy the connection string and fill in your username, password, and database name:
   ```text
   mongodb+srv://<USERNAME>:<PASSWORD>@<CLUSTER>.mongodb.net/forme_store?retryWrites=true&w=majority
   ```

### Step 2: Get AWS Credentials (Learner Lab / VocLabs)
1. Open your AWS Learner Lab and click **Start Lab** until the status circle turns **green**.
2. Click **AWS Details → Show** next to **AWS CLI**.
3. Copy the `[default]` credentials:
   - `aws_access_key_id`
   - `aws_secret_access_key`
   - `aws_session_token`

### Step 3: Add GitHub Secrets & Variables
Open your GitHub repository → **Settings → Secrets and variables → Actions**:

**Secrets** (under the **Secrets** tab):
| Secret Name | Value |
|---|---|
| `AWS_ACCESS_KEY_ID` | `aws_access_key_id` from Step 2 |
| `AWS_SECRET_ACCESS_KEY` | `aws_secret_access_key` from Step 2 |
| `AWS_SESSION_TOKEN` | Full `aws_session_token` string from Step 2 |
| `MONGODB_URI` | MongoDB Atlas connection string from Step 1 |
| `JWT_SECRET` | Any long random string used to sign JWT tokens |

**Variable** (under the **Variables** tab):
| Variable Name | Value |
|---|---|
| `AWS_REGION` | `us-east-1` |

### Step 4: Push to `main` and Deploy
```bash
git add .
git commit -m "feat(hosting): configure AWS EC2 CloudFormation and CI/CD deployment"
git push origin main
```
Watch progress under the **Actions** tab in GitHub. First-time provisioning takes roughly 6–8 minutes; subsequent code pushes typically complete in 1–2 minutes.

### Step 5: Verify the Live Site
1. In the finished GitHub Actions run, expand **Print Live Web Application URL** and open `http://<EC2_IP>`.
2. Confirm the API is responding at `http://<EC2_IP>/api/health`.

## 8. Handling AWS Learner Lab Expiration (4-Hour Timeout)

AWS Learner Lab sessions expire after ~4 hours, stopping EC2 and invalidating temporary session keys. To restore your site:

1. Open the lab console and click **Start Lab** until green.
2. Click **AWS Details → Show** and copy the new `aws_access_key_id`, `aws_secret_access_key`, and `aws_session_token`.
3. Update those three secrets in GitHub (**Settings → Secrets and variables → Actions**).
4. Open the **Actions** tab in GitHub and click **Re-run all jobs** on the latest workflow (or click **Run workflow**).
5. CloudFormation finds the stack, fetches the new EC2 IP, updates `CLIENT_URL` in `backend/.env`, and restarts PM2 and Nginx automatically.

## 9. Troubleshooting Common Issues

| Problem | Cause | Solution |
|---|---|---|
| Browser shows `ERR_CONNECTION_REFUSED localhost:5000` | Frontend bundle fell back to localhost API URL | Verify `VITE_API_URL=/api` is set during build and `import.meta.env.PROD` fallback exists in `frontend/src/services/api.js` and `ProductImage.jsx`. |
| `502 Bad Gateway` | Nginx is up, but Express on port `5000` crashed or is stopped | Check `pm2 status` and `pm2 logs --lines 50` on EC2; most often caused by an invalid `MONGODB_URI`, missing Atlas `0.0.0.0/0` whitelist, or missing `JWT_SECRET`. |
| CORS blocked in browser | `CLIENT_URL` in `backend/.env` has an outdated EC2 IP | Re-run the GitHub Actions deploy job so `.env` regenerates with the current `$EC2_IP` and PM2 reloads with `--update-env`. |
| Uploaded images return `404` | Static file regex intercepts `/uploads/*.jpg\|png\|webp` | Confirm `location ^~ /uploads/` is present in `infra/nginx.conf`. |
| PM2 restarts repeatedly (`errored`) | Cluster mode used on a single-core `t2.micro` | Confirm `exec_mode: 'fork'` and `instances: 1` in `backend/ecosystem.config.cjs`. |
| Page refresh on `/shop` or `/admin` returns `404` | Nginx missing SPA fallback | Confirm `try_files $uri $uri/ /index.html;` is inside `location /` in `infra/nginx.conf`. |
| Workflow fails on `git clone` during first boot | Repository is private | Make the GitHub repository public (or configure a read-only token in `ec2-instance.yaml`). |

## 10. Useful Server Maintenance Commands

Run these commands inside **EC2 Instance Connect**:

```bash
# Check PM2 process status
pm2 status

# View last 50 lines of backend logs (and stream new logs)
pm2 logs --lines 50

# Restart backend and reload environment variables
cd /var/www/app/backend && pm2 restart ecosystem.config.cjs --update-env

# Inspect first-boot CloudFormation UserData setup log
sudo cat /var/log/userdata.log

# Stream live Nginx traffic and error logs
sudo tail -f /var/log/nginx/access.log
sudo tail -f /var/log/nginx/error.log

# Test Nginx configuration syntax and reload safely
sudo nginx -t && sudo systemctl reload nginx
```
